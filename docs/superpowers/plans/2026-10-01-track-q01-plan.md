### Task 1: Fix bucket initialization in `rate_limit.py`

**Files:**
- Modify: `services/ai-api/config/rate_limit.py`

**Interfaces:**
- Consumes: existing rate-limiter class (or module-level state) that constructs `tokens` from `capacity`.
- Produces: bucket that starts with `max(0, capacity - burst)` tokens.

- [ ] **Step 1: Inspect the bucket initialization**

Run: `grep -n "tokens\|capacity\|burst\|__init__" services/ai-api/config/rate_limit.py | head -30`

Identify the exact line that sets `self.tokens` (or equivalent). Note the variable name. If the rate limiter is implemented as a closure, find the equivalent initialization.

- [ ] **Step 2: Inspect the test file to understand expected behavior**

Run: `cat services/ai-api/config/__tests__/test_rate_limit.py`

Read each test in full. Note the 4 failing tests (`test_request_deny_returns_retry_after`, `test_request_refills_over_time`, `test_rate_limit_decorator_returns_429`, `test_rate_limit_decorator_handles_request_via_kwarg`) and the 2 passing tests. For each failing test, identify the assertion that expects 429 vs 200, and how many requests the test makes before that assertion.

- [ ] **Step 3: Change bucket initialization**

Open `services/ai-api/config/rate_limit.py`. Locate the line(s) that set `self.tokens = ...` (or equivalent). Replace with:

```python
self.tokens = max(0, self.capacity - self.burst)
```

If the file uses a different variable name (e.g., `self._tokens`, `self.tokens_remaining`, or a closure variable `tokens`), substitute that variable name in the replacement. Do not rename variables.

If the file does not store `tokens` as an attribute (e.g., a simple function returning a count), apply the equivalent change: the bucket starts with `max(0, capacity - burst)` instead of `capacity`.

Expected: `6 passed` (was `4 failed, 2 passed`).
