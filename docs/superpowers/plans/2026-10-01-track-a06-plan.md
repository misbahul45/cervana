**Files:**
- Modify: `services/api/prisma/seed.ts` (entire file body)

**Interfaces:**
- Consumes: `services/api/prisma/seed-golden-graph.ts` (default-exported by side effect: `main()` at top level); `services/api/prisma/seed-theme.ts` (same).
- Produces: a `seed.ts` whose `main()` only triggers the two scripts above and exits.

- The body of `async function main()` that creates the SKKNI topic/sub-topic/lesson/step rows.

- [ ] **Step 2: Delete the SKKNI block and helpers**

Remove from `services/api/prisma/seed.ts`:

1. All SKKNI constants (`subTopicMap`, `lessonStructure`, `lessonIds`, `subTopicsId`, `themesData`).
2. All SKKNI helpers (`generateSKKNIDescription`, `generateSubTopicDescription` if it was SKKNI-only).
3. The body of `main()` that creates SKKNI rows.
4. Any unused imports that were referenced only by the deleted block (e.g., `import { generateSKKNIDescription } from ...` if such import existed).
5. Any unused `ref` / `computed` / helper imports the linter flags after the deletion (verify with `pnpm build` in step 4).

After deletion, the file should be much shorter (estimate 30–80 lines).

- [ ] **Step 3: Replace `main()` with a thin wrapper**

Replace `async function main()` and its invocation block with a thin wrapper that dynamically imports the two scripts:

```ts
async function main(): Promise<void> {
  await import('./seed-golden-graph');
  await import('./seed-theme');
}

main().catch((error) => {
  console.error('seed failed:', error);
  process.exit(1);
});
```

Rationale: each imported script's own top-level `main()` connects to Prisma, runs its upsert logic, and disconnects via `.finally()`. The wrapper here only sequences the imports and forwards exit-on-failure.
